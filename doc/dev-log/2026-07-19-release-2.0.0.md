# 2026-07-19 — Release 2.0.0 (packages + app, all stores)

First **major** bump of the suite. Lockstep release of the seven pub.dev
packages and the standalone app to 2.0.0, cut from `main` at ~40 commits past
the 1.4.7 tag.

## Why major

`dart_pdf_editor` removed the `PdfEditingController` pure style forwarders
(#317) — a documented **breaking** API removal (read/write those ~19 tool-style
properties through `controller.preferences.<name>` now). Under the lockstep
one-version rule a breaking change in any package moves the whole suite, so all
seven went 1.4.7 → 2.0.0 and the app to 2.0.0+18.

## What shipped

- **pub.dev:** `pdf_cos`, `pdf_test_fixtures`, `pdf_document`, `pdf_graphics`,
  `dart_pdf_editor`, `pdf_ocr_vlm`, `pdf_ocr_ondevice` all at **2.0.0**,
  published via the manual path (`tool/release.sh --publish --yes`). Clean run,
  no hang (the `--max-time 30` curl fix from 1.4.6 is in). All 7 `<pkg>-v2.0.0`
  tags pushed.
- **App:** `2.0.0+18`. Google Play internal-track draft (version code 18),
  App Store Connect iOS + macOS builds uploaded, and the `app-v2.0.0` GitHub
  Release published with the desktop/web/APK artifacts.

## Notes / gotchas for next time

- **The major bump needs the dev-dependency ranges widened, or the workspace
  won't resolve.** `pdf_cos`/`pdf_graphics`/`pdf_document`/`dart_pdf_editor`/
  the two OCR packages dev-depend on `pdf_test_fixtures` (and `pdf_graphics`)
  at `^1.4.0`, which excludes the local 2.0.0 → `pub get` fails. But you can't
  just pin them to `^2.0.0`: `release.sh` publishes with **hosted** resolution
  (it waits for each version to appear on pub.dev), and `pdf_cos` publishes
  *before* `pdf_test_fixtures`, so its dev-dep must resolve against an
  already-live version. Fix: widen to `'>=1.4.0 <3.0.0'` — admits the local
  2.0.0 for workspace tests and lets `pdf_cos` publish against the live 1.4.7
  fixtures. This is the publish-ordering cycle the lockstep-check exemption
  warns about, surfacing for real only on a major bump.
- **Changelogs were under-filled again.** Only `dart_pdf_editor` had an
  `## Unreleased` section (and even that missed several public changes merged
  after it — tile pyramid default-on, progressive open, `PdfEditToolBehavior`,
  keyless/self-signed signing UI, dockable panels). `pdf_cos` (+2600 lines),
  `pdf_document`, `pdf_graphics`, and `pdf_test_fixtures` had real API additions
  and **no** unreleased entries. Reconstructed ~5 package sections from commit
  messages + CLAUDE.md at release time. Same nudge as 1.4.7: get PR authors to
  add their line.
- **Ghent local golden: 4 mismatches, non-blocking.**
  `dart_pdf_editor/test/ghent_render_test.dart` failed on
  `GWG166_Softmasks_Images_DeviceCMYK`, `GWG169_Softmasks_Vector_part2`,
  `GWG181_16Bit_DeviceCMYK`, and `GWG030_Gray_K_black_OP`. This is a
  **local-macOS-only** golden — under CI the pixel diff is skipped
  (`CI != 'true'`), so it gates neither CI, `tool/release.sh` (which gates on
  `analyze`), nor the store builds. All four render non-blank; the failures are
  colour-fidelity drift in the exact category the `_knownBaselineDeviations`
  set already covers. GWG166/181 are the expected result of the #370 YCCK/CMYK
  JPEG decode fix against 14-Jun baselines that were never re-seeded; GWG030 is
  the pre-existing open deviation; GWG169 is a sibling vector-softmask
  deviation. **Did not** re-baseline or add to the deviation set as part of the
  release — that's a reviewable rendering decision (and GWG030 shouldn't be
  baselined away). Follow-up: visually review and `GHENT_UPDATE=1` re-seed
  GWG166/181/169 in a separate PR.
- Store build recipe from [[dartpdf-store-release]] worked verbatim: AAB via
  `flutter build appbundle --release` (onnxruntime `libonnxruntime.so` still
  17.5 MB / `2**14`-aligned in `base/lib/arm64-v8a/` — 16 KB page size OK),
  IPA via `flutter build ipa --release --export-method app-store`, macOS via
  `flutter build macos` → `xcodebuild archive` → `-exportArchive` (method
  `app-store-connect`, team N5K9GK8B27, reused the 1.4.7 ExportOptions.plist) →
  pkg. Uploads via the turnkey `app_store_upload.sh` / `google_play_upload.sh`
  (Play SA key base64 in the login keychain, `dartpdf-google-play-sa`).
