# 2026-07-25 - Landing site 404 page

Added `site/404.html`, the not-found page for `dart-pdf.com`. Firebase Hosting
picks up a `404.html` at the root of the deploy directory automatically and
serves it with a real 404 status for any URL that doesn't match a file - no
`firebase.json` change needed (`public` is already `.`, and the `ignore` list
doesn't touch it).

## Shape

Same self-contained pattern as `support.html` / `privacy.html`: inline `<style>`
with the site's design tokens, the shared header (brand mark + language
switcher) and footer, `/i18n.js` at the bottom. Content is a gradient "404"
with the DartPDF sheet mark standing in for the middle 0, a headline, a lede
that reassures the reader their PDFs are fine (they never left the device), two
CTAs (home, browser app), and a six-card grid of popular destinations
(features, download, support, SDK, privacy, source).

## Gotchas worth remembering

- **Every link is root-absolute.** A 404 page is served *at the requested URL*,
  so it can render at any path depth; a relative `support.html` would resolve
  against `/some/missing/dir/`. All hrefs are `/`, `/support`, `/#download`, etc.
  (`cleanUrls: true` in `firebase.json` makes the extension-less forms right).
- `noindex, follow` in the robots meta, no `<link rel=canonical>`, and it is
  deliberately absent from `sitemap.xml`.
- 18 new `nf_*` keys in `i18n/en.json` plus all 19 locale files; `nav_openBrowser`
  and `back_to` are reused. `nf_h1` carries the `<span class="hl">` amber
  underline, so every translation keeps that span - `i18n/_validate.py` checks
  the tag multiset and passes.
- The header's "Back to DartPDF" link is hidden below 640px (it wrapped and
  crowded the language switcher); the brand mark and the primary CTA both go
  home, so nothing is lost.

Verified by rendering in real Chromium at 1280x900 and 390x844, in `en`, `ja`,
and `ar` (RTL) - layout, i18n application, and the `<title>` swap all check out.
