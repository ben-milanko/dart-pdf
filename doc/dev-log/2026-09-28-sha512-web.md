# SHA-384/512 on 32-bit halves for the web (R6 opens about 7x faster in JS)

Algorithm 2.B, the revision 6 (AES-256) password hash, runs 64+ rounds of
AES-CBC followed by SHA-256, SHA-384 or SHA-512 over each round's 1-7 KB
block. One empty-password open hashes roughly 280 KB with SHA-384/512.
package:crypto's web build (`sha512_slowsinks.dart`, picked when
`dart.library.js_interop` is defined) emulates every 64-bit add, shift and
rotate with `Uint32List` helper calls, which runs at about 4-5 MB/s under
dart2js in node here, against about 90 MB/s natively. After the AES T-table
change (#973) that emulation was about 85% of an R6 open in the browser.

## What changed

- `pdf_cos/lib/src/crypto/sha512_js.dart`: one-shot `sha512Js` and
  `sha384Js`. Each 64-bit word is a high and a low 32-bit half held in
  locals; rotations combine `>>>` and `<<` across the pair, and the low
  half's carry goes into the high half by dividing the sum by 2^32. The 80
  round constants and the 160-entry schedule are top-level `Uint32List`s.
  SHA-384 is the same compression function with its own IV, truncated to 48
  bytes.
- `sha2_digest.dart` is a conditional export in the same shape as
  `zlib_inflate.dart`: `sha2_digest_io.dart` on the VM,
  `sha2_digest_web.dart` under `dart.library.js_interop`. Both expose
  `List<int> sha2Digest(crypto.Hash hash, List<int> data)`. The io side is
  `hash.convert(data).bytes`. The web side sends `identical(hash,
  crypto.sha512)` and `identical(hash, crypto.sha384)` to `sha512_js.dart`
  and everything else to package:crypto.
- `StandardSecurityHandler._hash2B` routes its SHA-384 and SHA-512 arms
  through `sha2Digest`. SHA-256 stays on package:crypto, which is already
  fast in JS.

Kept on purpose:

- **Native stays on package:crypto.** The halves implementation is 1.3x
  slower than package:crypto on AOT (4 MB: 45.8 vs 60.3 ms), so it is
  web-only. The VM path is byte-for-byte the code it was.
- **The `Hash` objects are not replaced.** CMS digest OIDs, the X.509 builder
  and the ECDSA nonce HMAC switch on package:crypto's `sha384`/`sha512`
  identity, so the facade dispatches on them instead.
- **Only `_hash2B` is routed.** `cmsVerify`'s content digest and `tsp.dart`
  are left alone: no signature in the checked-in corpora or a private
  real-world corpus uses SHA-384/512, and cms.dart has another owner this
  round. Routing them later is a one-line change per call site.
- **dart2wasm also takes the web side** (it defines `js_interop` too), the
  same choice package:crypto makes for its slow sinks. The code masks
  explicitly, so it is correct there; the app ships JS.

## Correctness

- `test/sha512_js_test.dart` imports `sha512_js.dart` directly, so the VM run
  checks it against package:crypto's native 64-bit code:
  - every length 0-300, which covers the 111/112 and 127/128 padding
    boundaries;
  - 60 random lengths up to 20 KB plus the 1-7 KB block sizes 2.B hashes;
  - the FIPS 180-4 "abc" vectors for both hashes;
  - `sha2Digest` leaves SHA-1/SHA-256 on package:crypto;
  - a 2.B loop computed with either SHA implementation, over random
    passwords and salts, with and without the 48-byte /U owner input;
  - the R6 fixture opening with the empty user password, a user password and
    the owner password, and rejecting a wrong one.
- CI already runs `dart test -p node test/zlib_inflate_test.dart` for
  pdf_cos. The new file is appended to that step, which is where the
  conditional export actually picks the web side. It imports
  `pdf_test_fixtures/src/encrypted.dart` directly because the fixtures barrel
  exports 64-bit integer literals that dart2js rejects.
- A scratch dump hashed every indirect object (strings, names, numbers and
  decoded stream payloads) of the six pdf.js R6 files that open
  (empty_protected, encrypted-attachment, issue6010_1/2, issue7665,
  secHandler). print_protection needs a password and is rejected the same way
  on every leg. The dumps are identical for base and branch on JIT, AOT and
  dart2js `-O3`/`-O4`.

## Measurements

Scratch A/B: base worktree at cc144ae7 (main) against this branch, one bench
source compiled per worktree. dart2js legs run in node 26 and time process
CPU (`process.cpuUsage`); AOT legs time thread CPU. 7 interleaved ABAB rounds
with alternating order; each figure is the median of per-round medians and
the ratio is the median per-round branch/base. Load average 10-12 on 10
cores.

| workload | base ms | branch ms | branch/base |
|---|---|---|---|
| R6 fixture open + page 0 content, `-O3` | 72.9 | 10.3 | 0.140 (7.2x) |
| R6 fixture open + page 0 content, `-O4` | 63.0 | 10.1 | 0.161 (6.2x) |
| six pdf.js R6 opens + print_protection reject, `-O3` | 545.7 | 72.2 | 0.132 (7.6x) |
| the same, `-O4` | 469.3 | 70.3 | 0.150 (6.7x) |
| R6 fixture open, AOT | 9.87 | 9.94 | 1.007 |
| pdf.js R6 set, AOT | 76.2 | 76.6 | 1.001 |

SHA-512 over 4 MB, in-process package:crypto vs `sha512Js` (7 reps): `-O3`
937.7 -> 70.8 ms (0.075x), `-O4` 799.4 -> 65.1 ms (0.081x), AOT 45.8 ->
60.3 ms (1.32x slower, hence web-only).

## Where the saving lands

About 60 ms of CPU per Algorithm 2.B open in the browser (more on a phone).
The web render worker now updates its revision in place
(`2026-09-28-web-worker-revision-update.md`), so an ordinary edit no longer
reopens the document in a fresh worker. 2.B is still paid:

- on the UI isolate's first open of the document;
- once in each web render worker's `init` (the pool has up to 3 lanes);
- by the web worker's undo re-open, which opens the shorter prefix;
- by the compression worker's open;
- by the sign-path reopens in the editing controller.

UI-side undo does not re-derive the keys since #975 (`openAppended`), so it
gains nothing here.

## Not done

- Sending the derived file key to the workers in `init` would remove 2.B from
  worker starts entirely. It puts key material on a message port, which is a
  separate trust decision (see `2026-09-26-aes-ttable.md`).
- `cmsVerify`/`tsp.dart` digests (see above).
- Breadth: only R6 documents benefit. None of a private real-world corpus of
  about 50 files is encrypted, and the app only opens owner-password files
  (empty user password), since it has no password prompt.
