# 2026-07-16 — Release 1.4.7 (packages + app, all stores)

Full lockstep release of the seven pub.dev packages and the standalone app,
cut from `main` at 22 unreleased commits past the 1.4.6 tag (a 23rd, #321's
`PdfRenderTrace`, landed on `main` mid-cut and was folded in via rebase).

## What shipped

- **pub.dev:** `pdf_cos`, `pdf_test_fixtures`, `pdf_document`, `pdf_graphics`,
  `dart_pdf_editor`, `pdf_ocr_vlm`, `pdf_ocr_ondevice` all at **1.4.7**,
  published via the manual path (`tool/release.sh --publish --yes`).
- **App:** `1.4.7+17`. Google Play internal-track draft (version code 17),
  App Store Connect iOS + macOS builds uploaded, and the `app-v1.4.7` GitHub
  Release ("DartPDF 1.4.7") published with the desktop/web/APK artifacts.

## Notes / gotchas for next time

- **Changelogs were badly under-filled.** Only 4/19 `dart_pdf_editor` and 1/7
  `pdf_document` commits since 1.4.6 had added an `## Unreleased` entry, and
  `pdf_graphics` and `app` had none at all despite real changes. The release
  step had to author ~20 entries from commit messages. Nudge PR authors to add
  their changelog line, or expect to reconstruct it at release time.
- **`#291` (native printing / drop PDFium) was never compiled in CI** — PR CI
  builds only web + Dart on Ubuntu, so the per-platform native print runners
  (Windows/macOS/iOS/Android/Linux method-channel code) first compiled during
  the store builds. macOS archive and iOS `flutter build ipa` both succeeded,
  so those two runners are good; Windows/Linux still unverified by a build.
- **Tag-triggered `publish-pub.yml` runs FAIL on the manual path, expectedly.**
  The `check-publish-needed / Verify tag points at deploy history` guard rejects
  `<pkg>-v1.4.7` because the `Release 1.4.7` commit is on `main`, not on the
  `deploy` branch (`… points at <sha>, which is not on the deploy branch
  history`). Harmless — the packages were already published manually. This is a
  deploy-history guard, distinct from the still-open OIDC "publishing from
  github is not enabled" gap.
- Applied the memory-noted `--max-time 30` fix to `pub_has_version`'s curl in
  `tool/release.sh` (separate commit) so a stalled pub.dev probe can no longer
  hang the publish loop indefinitely. The run itself was clean — no hang.
- Store build recipe from [[dartpdf-store-release]] worked verbatim: AAB via
  `flutter build appbundle --release` (16 KB-aligned onnxruntime carried
  through, LOAD `2**14`), IPA via `flutter build ipa --release
  --export-method app-store`, macOS via `flutter build macos` →
  `xcodebuild archive` → `-exportArchive` (method `app-store-connect`, team
  N5K9GK8B27) → pkg. Uploads via the turnkey `app_store_upload.sh` /
  `google_play_upload.sh`.
